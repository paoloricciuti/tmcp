## Rewrite `@tmcp/transport-cli`

Recommended direction: replace the current schema-to-flags CLI with a small static, agent-first command surface that accepts JSON input as a positional argument, exposes tool schemas explicitly, and removes most of the shallow manual coercion/validation logic from `packages/transport-cli/src/index.js`.

### Goals

- Follow the GitHub feedback from JReinhold: prefer JSON input over dynamic flags, add schema introspection, support light output shaping, and keep the CLI easy for agents to drive.
- Make this a clean breaking redesign; do not keep the old schema-derived flag mode.
- Keep the existing in-process MCP transport architecture (`initialize`/`tools/list`/`tools/call` via `server.receive(...)`) rather than redesigning the transport boundary.
- Fix protocol rough edges while touching the command flow: send `notifications/initialized` and page through `tools/list` results.

### Command Model

- Add static commands in `packages/transport-cli/src/index.js`:
  - `tools`
  - `schema <tool>`
  - `call <tool> [input]`
- Keep bare `<tool>` as an alias for `call <tool>` so invoking a tool still feels direct.
- Tool invocation should accept one JSON input source at a time, with the positional argument as the primary UX:
  - `call greet '{"name":"Alice"}'`
  - `greet '{"name":"Alice"}'`
  - `--input-file path/to/input.json`
  - stdin when piped and no explicit input was provided
- Add lightweight output controls for tool calls:
  - `--output full|structured|content|text`
  - `--fields path1,path2` using comma-separated dot paths only
- Treat `--dry-run` as optional and only wire it if the transport gains an explicit context-mapping hook.

### File Changes

1. `packages/transport-cli/src/index.js`
   - Remove `build_option`, `coerce_args`, `validate_required`, and `validate_enums` from the main flow.
   - Add helpers for MCP notifications, paginated tool discovery, JSON input resolution, output selection, and field filtering.
   - Restructure `run(ctx, argv)` around static commands plus per-tool alias routing.
   - Keep error handling via stderr and `process.exitCode = 1`, but distinguish JSON parse, unknown tool, unsupported output mode, and MCP errors.

2. `packages/transport-cli/src/internal.d.ts`
   - Expand the internal tool/schema typing beyond the current shallow `InputSchema` shape.
   - Include the list response pagination shape and tool metadata used by `schema` output.

3. `packages/transport-cli/test/index.test.js`
   - Replace flag-based expectations with JSON-input and schema-introspection coverage.
   - Add tests for `tools`, `schema <tool>`, `call <tool>`, bare tool alias, stdin input, input-file input, output modes, field filtering, initialization notification ordering, pagination, and failure paths.

4. `packages/transport-cli/README.md`
   - Rewrite the docs around the new JSON-input UX.
   - Remove stale yargs language and document the actual command surface, output modes, and input sources.

5. `packages/transport-cli/package.json`
   - Update package description/keywords only if the new UX needs clearer metadata.

6. `packages/transport-cli/src/types/index.d.ts`
   - Regenerate after implementation so public typings match any constructor or JSDoc changes.

### Main Implementation Notes

- Default output should remain `full` so the CLI stays lossless and closer to current behavior.
- Prefer the first positional argument for JSON input; `--input-file` and piped stdin act as fallbacks for larger payloads or shell ergonomics.
- `schema <tool>` should print the tool metadata and JSON schemas as pretty JSON rather than inventing a custom summary format.
- `--output text` should only succeed for text-only content blocks; otherwise it should fail with a clear stderr message.
- `--fields` should stay intentionally small in scope; do not introduce jq/JSONPath semantics unless there is a strong reason.
- If `--dry-run` is implemented, prefer a constructor option like `new CliTransport(server, { map_context })` so CLI flags can project into `ctx.custom` explicitly.

### Risks

- The biggest product decision is whether this is a clean break or whether old schema-derived flags need a compatibility mode.
- Tool names may collide with static commands like `tools`, `schema`, or `call`; command precedence must be handled deliberately.
- stdin handling must avoid hanging interactive sessions by only reading when stdin is not a TTY.
- Pagination and lifecycle fixes should be covered by tests because they are easy to miss during a CLI-focused rewrite.

### Verification

- Run `pnpm --filter @tmcp/transport-cli test`.
- Run `pnpm --filter @tmcp/transport-cli generate:types`.
- Run `pnpm lint` and `pnpm typecheck` if the change reaches beyond local tests.
- Manual smoke checks after implementation:
  - invoke a tool with positional JSON input
  - invoke a tool via piped stdin
  - inspect a tool with `schema <tool>`
  - verify `--output text` and `--fields`
  - verify multi-page `tools/list` behavior with a mocked server test
